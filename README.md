# 作业打卡数据 · 自用备忘

这份说明是给自己备份的：以后每天把 **App 打卡名单**（截图或文字）发给助手，让助手把结果记进 **网页打卡表**，避免重复解释流程。

---

## 你要什么结果

- **分享用网页**：`attendance/分享_体育作业打卡.html`  
  浏览器打开即可看表；**有打卡**的格子显示 **🏆**，最后一列是累计次数。
- **原始数据**：按日期一个 JSON：`attendance/YYYY-MM-DD.json`（例如 `2026-04-18.json`）。

网页 **不会**自动联网读钉钉/班级群，只能靠你提供的名单或截图更新 JSON，再生成 HTML。

---

## 助手需要做的事（标准流程）

1. **对名单**  
   - 姓名必须与 `roster.csv` 里一致；若 App 显示别名（如「陈子屹」对应「陈语萌」），在 `app_aliases.json` 里维护映射，或直接在 JSON 里写**名册上的正式姓名**。

2. **写当天 JSON**（可基于已有文件改）  
   - `date`：当天 `YYYY-MM-DD`  
   - `activity`：例如 `4月18日数学作业`  
   - `present`：**字符串数组**，当天完成打卡的学生姓名（与 roster 一致）  
   - `absent`：可选；若维护则应为 `roster 全集 − present`（不维护也可，以 `present` 为准生成表）  
   - 其他字段（`grades`、`app_completed_count` 等）仅作备注存档；**生成网页时只认 `present`**，格子一律 **🏆**，不要擅自改成等级字。

3. **生成网页**  
   在项目根目录执行：

   ```bash
   cd /path/to/data
   python3 build_attendance_grid.py
   ```

   会重写 `attendance/分享_体育作业打卡.html`。  
   **依赖**：`pip install pypinyin`（脚本按拼音排学生行）。

4. **表结构说明（别改规则除非你有意为之）**  
   - `build_attendance_grid.py` 会读取 `attendance/` 下**所有**带 `date` + `present` 的 `.json`，按日期排成多列。  
   - 若某天的列标题是 `4.17` 且前面已有四天，会在 `4.16` 与 `4.17` 之间插一列空白，前四天都打卡则显示 **🚩**（脚本里写死的规则）。

---

## 你每天可以怎么发

任选一种即可：

- 发 **App 截图**（「已完成」列表尽量截全或说明未截全）。  
- 发 **一段文字**：逗号/换行分隔的姓名。  
- 说清日期：「这是 **4 月 18 日** 数学作业」。

助手根据截图/文字更新对应日期的 `present`，再跑一遍 `build_attendance_grid.py`。

**多张图、不同日期**：若你说明「图 A 的几个人算某日、图 B 算某日」，按你的对应关系分别写入各自的 `YYYY-MM-DD.json`，不要默认同一屏里所有名字都是同一天。

---

## 文件一览

| 路径 | 作用 |
|------|------|
| `roster.csv` | 全班姓名与序号（数据源） |
| `app_aliases.json` | App 显示名 → 名册姓名（可选） |
| `attendance/YYYY-MM-DD.json` | 某日打卡名单（`present` 为主） |
| `build_attendance_grid.py` | 汇总 JSON → 生成 `分享_体育作业打卡.html` |
| `attendance/分享_体育作业打卡.html` | 可截图分享的打卡表 |

---

## 易踩坑（以前翻过车的）

- **App 人数 ≠ 网页行数**：App「已完成 21 人」可能含家长端重复、或非本班条目；网页只给 **能对上 roster 的姓名** 打 🏆，数字对不齐时以**名册补全**为准，并在 JSON `mapping_notes` 里备注即可。  
- **不要**在生成逻辑里把格子改成「A+ / 待批改」之类，除非你自己改需求；默认 **只要交了就 🏆**。
